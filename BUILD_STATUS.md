**Guided reach calibration:** new sessions default to “Target accuracy”; setup also offers explicit “Reaction only.” Accuracy setup captures normal guard, then comfortable projected lead/rear straight-punch reach for the hands actually requested by that drill, with return-to-guard stages. Reach captures wait at least five seconds for the spoken instruction and a stable recent pose, allowing up to nine seconds before a steadiness failure. Initial capture requires three reliable samples spanning at least 400 ms; a >250 ms sample gap clears the recent pose. Each hand’s measured endpoint is stored relative to shoulder centre, anatomical shoulder axis and apparent shoulder width, with visible radius incorporating capture scatter and guidance level. Small projected travel or excessive body movement is rejected with an explanation rather than fabricated reach. A near-head-on view may not give enough measurable 2D arm travel; setup explains using a slight camera angle while keeping both shoulders and arms visible. Head/nose and both shoulders/elbows/hands are needed by the existing upper-body recognition/calibration; hips/legs remain unnecessary.

Between cues, a stable calibrated guard translates/scales the next target with the current body. A >25% apparent-scale change or >about 20° shoulder-axis change asks for reach recalibration. Source/orientation changes and pause/resume also invalidate reach. The target is frozen once prepared and bound to cue ID, hand, camera generation and calibration ID. Reach sampling stops through cue/result/reset so a normal punching follow-through cannot immediately rewrite or invalidate the calibration. Meaningful drift before the renderer acknowledges the cue returns to setup without a tracking-loss episode or missed punch. These bounds are unverified product policy, not measured accuracy claims.

**Recognition plus the displayed region:** the original reliable recognition gate, classifier confidence, hand/kind and response timing remain in place. Only a real accepted `rep_ok` action can receive a target result; crossing a ring alone never creates a punch. The worker matches the action ID (or its onset if unavailable), finds its actual extension-peak timestamp, and evaluates a bounded raw wrist segment bracketing that peak. It requires current in-bounds confidence >=0.3, both reliable endpoints, <=220 ms gap, bounded motion and compatible body alignment. It never interpolates across an unreliable observation. Geometry uses source-image-height units so the rendered circle and judging region agree despite image aspect and mirroring. No tiny exact single-frame overlap is required. Missing peak coverage, invalid geometry or uncertain alignment produces an aiming-unclear result and same-hand retry, not a target miss or inferred hit. The existing bounded tracking-loss behavior remains separate.

**Outcomes, storage and modes:** Ready → rendered Jab/Cross → explicit outcome (protected at least 2.6 seconds after result submission and until speech completes) → Reset → Ready/next cue. Recognised target reached, recognised target missed with measured above/below/left/right correction, recognised but aim unclear, movement not recognised, wrong hand, timeout and unreliable tracking are distinguishable. Directional aiming hints are generated only from reliable judged geometry. Aiming-unclear results preserve recognised movement in `PadAttempt.outcome` and an independent optional `targetMatch`, but do not complete a drill attempt or add a target miss; the same hand retries. Actual target misses complete an attempt and are visibly separate from recognition failure. Reaction mode shows a text cue without an aiming dot and judges recognition/onset only. Optional additive Codable fields preserve older records as reaction-only; no historical target hits are inferred. Shared saved recaps show mode, completed attempts, recognition totals, target reached/missed/unclear totals and ordered outcomes separately.

Pose age at delivery is shown: the live preview leads inference, so moving joints can trail the video; this overlay does not claim synchronized photon timing. Local PadTracking logs include target result, cue/calibration IDs and exact uncertainty reason. Stored target results include source geometry and the selected wrist point, not camera images/video or a full pose recording. ## Camera-assisted Learn and Live Pads integration — 21 October 2026

**Implemented:** Train's primary card opens camera-training setup; the jab, cross and jab–cross drill pages have a separate camera-practice action. Existing audio/manual guided practice remains available. Both Learn (bounded attempts, cued one at a time) and Live rounds (work/rest) use the recovered MoveNet/classifier/StepJudge pipeline. Full-screen available camera area, mirrored aspect-fill preview, pose-derived frozen aim guides, spoken callouts and immediate response/reset messages are connected. There is no original demonstration video or animated coach.

**Guidance levels:** user-adjustable Beginner/Intermediate/Advanced, suggested from profile. Beginner has a larger target, a wrist-to-aim guide, lead/rear instructions, spoken reset feedback, 6-second response allowance and 2.5-second reset. Intermediate uses 3 seconds / 1.5-second reset; Advanced uses compact targets and 1.8 seconds / 1-second reset. All retain the same 0.6 detector confidence threshold. These are original beta pacing defaults, not validated skill benchmarks. Targets guide aiming; overlap does not create a hit or a technique grade.

**Lifecycle/results:** SessionController/SessionPlayer own the new camera state; existing full-screen routing, interruption/background pause, periodic checkpoints and save-once history are reused. Camera results include renderer-token and source-generation boundaries; old/onset-before-cue/out-of-order events are rejected. Each target is drawn before its subsequent display-link acknowledgement opens the judge. This acknowledges renderer submission, not measured hardware presentation latency.
